# 横形Z方向平行度：独立ブラウザー監査

2026-10-07。製品コードの実装とは別担当が Chromium の実画面・実ボタンを検査。テスト: `tests/browser-horizontal-parallelism.cjs`。数値幾何の独立期待値は別記 `check-horizontal-parallel-independent.cjs` が担当し、本記録のブラウザー回帰だけを物理妥当性の証明としない。

## 検査範囲

- 旧公開HEADの生成HTMLを保存し、横形の既存欄が非表示であること、および他6機種を同一固有誤差・支持高さで測定した表示値を記録。
- 1280×1000、390×844、320×568で右上の既存触れ欄に「Z平行 / a 左右 / b 上下 / 始点0 / 走査300 mm」。文字折返し、支持点ボタン24px以上、横はみ出しなしを実画面とDOMで確認。
- 実ボタンで粗0.01 mm／微0.001 mm、上下往復の測定値復帰。設定サイドバーの実Zスライダー、実ファイル入力による保存JSON復帰。
- カメラ、ズーム、描画誇張の変更で値不変。理想状態でa,bとも0。
- 鞍＋前後曲率の支持高さでZ全域の有限値・位置依存性。端では300 mmを確保する始点へ戻す仮想配置であり、端から範囲外へ実部材を動かす意味ではない。
- 横形→既存5種→旋盤→横形の移動でラベルと測定方式復帰。他6機種の数値不変、5種の手前0、手前面外時は4方向すべて数値抑止、旋盤に追加欄なし。
- 展開図は既存スクロール領域に表示される。小画面では図と説明をスクロールして読む。下端まで読めること、上下支持操作が残ることを確認。

## レビューで直した点

- 当初SVGの「0」が計器本体の近くにあり接触位置を特定しにくかった。実装担当へ指摘し、バー下面の接触点に●を付けて0を隣接させた。
- 初期のZ移動テスト支持値がほぼ平面となり、丸め誤差だけでも「値が変わる」を満たし得た。独立テストを鞍＋前後曲率と有意差0.0001 µm超へ修正。
- 数値とラベルの上端を厳密一致としたテストが中央揃えの1px差を誤検知。実表示の重なり・折返し・枠外条件へ変更。

## 実操作例

固有XY=33、XZ=75、YZ=-15 µm、初期支持高さ0、軸中央で、A支持を粗1回上げると a=-75.00285→-76.34233 µm、b=+14.88750→+12.32914 µm。微1回では a=-75.13679、b=+14.63167 µm。小数の値は検証記録用で、製品欄は従来どおり整数µm表示。

## 限界

写真の実機・器具の実寸や干渉を再現した証明ではない。仮想テストバー固定＋パレット計器の有限走査。主軸の回転振れ検査ではなく、方向別a/bのZ送り平行度。実ブラウザー確認はChromiumであり、実iPhone Safariの機種別確認は未実施。

最終HTMLのSHA256、各判定、スクリーンショットは `browser-after/results.json` および同フォルダーのPNGを参照。

## 最終再確認

最終HTML SHA256 `5f602fd71182c73ce8825d0e58d7251a5b41535c9c6f0877cda6a54c890b6bd0` で62/62項目一致、ブラウザー例外0。修正後の●0が始点のバー下面接触点にあり、終点の白丸と区別できることを390pxの実画面で視認。鞍＋曲率のZ走査例ではb=-14.62279→-30.65529 µmと位置依存の変化を確認。始点clamp説明も実HTMLに含む。
