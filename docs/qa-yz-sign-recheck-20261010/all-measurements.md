# 全7機種の測定符号棚卸し（独立担当、2026-10-10）

対象は PR #32 の `874d659` 時点。製品は編集していない。[実行可能な診断](../../tests/diagnose-all-measurement-signs-20261010.cjs)と[生データ・入力・ソースハッシュ](all-measurements.json)を残した。

**圧縮を＋とする接触計算を一括反転する根拠は見つからなかった。ただし、これで横形YZの測定配置がユーザーの意図どおりと認定してはいけない。** 以下は「現在コードが置いた面・計器」に対する符号の監査であり、その面をR/Sのどちらに選ぶべきかは別の検証事項である。今回の横形YZの現物配置の確認は別担当が行う。

この表は現在の実装の読み出しだけで生成していない。基準器と計器の搭載先、実際の軸方向から作った別の所有者・方向表を、18個の設定値に照合した。機種の軸名が違うため、例えば門形Xと横形Xを同じ世界方向と扱っていない。

## 数字と図の境界で残る注意点

`squarenessMicronText` は絶対値を四捨五入して符号を戻し、負の0は出さない。−0.5→−1、＋0.5→＋1、±0.4999→0を直接確認した。単純な JavaScript `Math.round(raw)` と負の半端値の結果が違う。TIRと範囲は非負整数、上面点・接触指示・芯差は符号付き整数である。

`referenceDiagram` はS面を固定した展開図。図の右はS面法線、図の上は正の走査軸。横形YZでは**図の右＝実機上、図の上＝実機奥**である。本体と接触点の相対位置を法線へ射影し、測定子姿勢を別に描く。カメラの正面・側面と同じ投影ではない。今回の全状態で図に保存する本体法線位置と実際の面・本体座標を照合した。

局所角度図の `squarenessReference` では横形YZの「正＝下、負＝上」、測定小図では「押込＋＝上」となっている。これは前者が正の軸同士の角度の開き、後者が計器の圧縮だからである。ただし同じ「YZ」に逆向きの正負が併存することは読み違いの候補として統括へ報告した。ユーザーの指摘の原因と断定していない。

例として平坦支持、used/seed 123456 の横形YZは、局所角度−47.0666667 µrad（300 mm換算−14.12 µm）と、現在の上側計器による指示＋14.119999995 µm。この値の違いは符号を後から掛けたものではなく、選ばれた測定配置に対する接触距離に存在する。**その配置を採用してよいという検証とは別である。**

補助数字も混同しない。水準器は右高／奥高を＋とする勾配 mm/m、ねじれは奥−手前の横断勾配差、残差・真直度・傾きの影響例・評価RMSは大きさであってダイヤル符号ではない。局所軸角度は `acos(軸同士の内積)−90°`。全140状態で局所軸角度もこの定義へ照合した。別に四隅へ `h=±(0.01x+0.02z+0.03xz) mm` を与え、lr=±0.01、fb=±0.02、ねじれ=±0.06 mm/m、残差0.03 mm、影響例の非負を確認した。右高の支持で直立部材が左へ、奥高で手前へ倒れる法線方向も確認した。これらをダイヤルの正負に合わせて一括反転する修正は不適切。

## 実行結果と限界

理想／used seed 123456、中央／X57 Y43 Z29、平坦／支持B±0.010 mm／`h=±0.01xz mm` の全7機種140状態。960測定行、最小例・局所角度・固有TIR・支持勾配を含む1,944比較で不一致0、最大差 `4.0245673460503895e−10 µm`。現在の面・円筒座標を入力に、製品の接触式や符号表を使わない距離二分探索と照合した。接触面から外れた状態の表示可否はそのまま記録している。

この結果だけで「全て正しい」とは言わない。基準器の向き・R/Sの選択・どちらの部材を送るかを違えても、採用した配置の内部では上記計算は一致する。そのため横形YZは、ユーザーが求める基準と実送りの配置を独立に決めた監査結果と合わせて判定する。この担当は他5機種と製品コードを変更していない。実ブラウザー操作・公開版とPR版の区別・画像は別担当の記録を参照する。
