# 横形YZの可視DOM・改善文・3D方向の追跡

独立確認担当による追加調査。最初の [全項目符号監査](all-measurements.md)は変更せず、画面の可視性を再確認した結果と、現測定配置のまま再現する説明の欠陥を記録する。修正前は PR `874d659` の [保全HTML](browser/pr/index.html.gz)をChromiumに読み込んだ。

## 確定した欠陥

上段のYZは300 mm有限走査のダイヤル指示だが、微調整欄の同じ「YZ」の改善文は現在位置の局所角度で判定していた。「YZ：初期より直角に近づいた」という可視文には、評価対象が上段の測定とは別の局所角度だとの限定がない。**上段の実測定がゼロから離れた操作を、同じYZの説明が『近づいた』と表示する。** 数値の符号を逆転した不具合とは分ける。

初期個体の指定はテスト初期化。以降は実ブラウザーで設定メニューの「粗調整の手本を試す」をクリックして全支持を0にし、設定を閉じ、微調整を選び、設定の「調整の状態・手本」を開いた。

共通条件：横形、used個体、X=0、Y=0、Z=75、標準寸法。初期／現在のどちらも同じZ位置に対しR合わせと始点ゼロを取り直す。有限走査はZ部材位置 +150→+450 mm（Zスライダー約33.333→100）。現在位置Z75の局所角度とは評価位置も異なる。

seed2の局所角度は−12.751095616→+34.530000000 µradで絶対値が増える。seed3は−30.869893828→−24.756666667 µradで絶対値が減る。旧文はこの別量に従っていた。

## DOMと見える画面の区別

旧seed3手本後の問題箇所は次の可視DOM。

```html
<p class="fine-pair-reading better" data-pair="YZ"
   data-before="-30.86989382761749"
   data-current="-24.75666666666667"
   data-delta="6.113227160950817"
   data-trend="better" data-direction="opened">
  YZ：初期より直角に近づいた
</p>
```

上段 `.live-pair-values[data-pair="YZ"] .live-pair-error-value` は同じ状態で `+7`、`data-reading-microns="7.426999999615713"`。微調整欄と上段にはデータの種類が違うことを結び付ける説明がない。

一方、`#accuracy-current-YZ` の小数µm値は祖先 `.accuracy-card` が `hidden` で、通常UIに現れない。**局所角度換算の負数とダイヤル正数が二つの精度欄で同時に表示されている、という数値誤表示は確認していない。** 先の監査で挙げた「正＝下／押込＋＝上」の併存はこの可視性を区別する必要がある。

`#accuracyDiagram` は微調整の「局所軸角度を確認」を開くと可視。見出しは「YZ · 局所角度」、補足 `#localSquarenessNote` は「有限走査の測定図・指示値とは別」と明記。実際の通常図には「＋」「−」がそれぞれ理想点の下側／上側に置かれ、「＋下」「−上」という単語は詳細表示用定数から通常図へそのまま表示されていない。この図自体をダイヤル圧縮図と誤表示したという結論にはしない。

画像は [seed3初期+2](browser/fine-summary/before/seed3-initial.png)、[手本後の微調整文](browser/fine-summary/before/seed3-flat-fine.png)、[同じ状態で設定を閉じた上段+7](browser/fine-summary/before/seed3-flat-main.png)、[局所角度を開いた状態](browser/fine-summary/before/seed3-flat-local.png)。[seed2初期+25](browser/fine-summary/before/seed2-initial.png)、[旧「離れた」](browser/fine-summary/before/seed2-flat-fine.png)、[同状態の上段−10](browser/fine-summary/before/seed2-flat-main.png)も保管。[DOM・座標の全記録](browser/fine-summary/before/results.json)。

設定を開くと主画面が縮小され、今回の1280×1000撮影では上段数値の下部がクリップされる場合があった。Playwrightの`isVisible`だけではクリップを否定できないため、「一枚の画像で両方の数字が読める」とは主張しない。同じ機械状態で設定を閉じた画面と、開いた微調整文を分けて記録した。

## 3D主軸頭と矢印の対応

seed3初期の物理Y送り単位ベクトルは `(0.000097500146896, 0.999999995022, −0.000021195652071)`。主軸頭の同じ材料点をYへ微小送りした差分も同じ方向であり、前後倒れは前倒れ+21.195652173 µrad。支持を全て0にするとYの奥成分は0、前後倒れも0になる。3DのY矢印の奥成分も負→0で、表示誇張は約束した姿勢を拡大している。

ただしYZは主軸頭単体の床に対する倒れではない。seed3のパレットZ方向は初期の上成分 `+0.000052060201320` から手本後 `+0.000024752729795` へ変わる。3DのZ矢印も上成分が正のまま小さくなる。局所角度図ではYを基準へ固定してZを投影し、理想点y=54.4に対して実点がy=50.245→51.039（画面yは下へ増加）へ近づく。この意味で局所図は改善している。

上段の有限測定は同じYを使ってR合わせを行った器具に対し、パレットの300 mm移動・姿勢変化を含む接触を比較する。現在位置の軸角度だけで算出していない。前倒れが小さくなった事実を、そのまま有限指示が改善した説明へ置き換えたことが今回の混在である。Y矢印の世界方向、局所角度図の投影、ダイヤル圧縮方向の三つを一つの正負として扱わない。

## 修正後の独立再確認

修正担当は横形の微調整文を、上段と同じ有限測定の初期／現在の生値絶対値で比較する変更を実施。局所角度図、上段測定式、総合評価・探索には変更しない。

統合HTML `37bfa01052c53a55eddd770d015338f719d2d6495b8042525389a734583ecb8f` を [独立ブラウザー検証](../../tests/verify-yz-fine-summary-independent-20261010.cjs)で実行。25状態、446チェックが通り、ブラウザー例外0。上段生値と独立接触計算の最大差は2.0817×10⁻¹⁰ µm。[結果・全DOM・入力・始終点](browser/fine-summary/after/results.json)と[検証したHTML](browser/fine-summary/after/index.html.gz)を保管した。

|再現条件|修正前|修正後|
|---|---|---|
|seed2：+25→−10|直角から離れた|YZ測定：初期よりゼロに近づいた|
|seed3：+2→+7|直角に近づいた|YZ測定：初期よりゼロから離れた|

独立確認では、面と本体の座標から測定子の伸びを二分探索し、その絶対値の初期との差で必要な良化／悪化を判定した。製品の改善文関数を期待値にしていない。修正後画像は [seed2の改善文](browser/fine-summary/after/seed2-flat-fine.png)、[seed3の悪化文](browser/fine-summary/after/seed3-flat-fine.png)、[seed3の上段+7](browser/fine-summary/after/seed3-flat-main.png)。

実スライダーにHome／End／←を入力してZ−100／+100／+99、YにHomeを入力してY−100へ移動。全3測定で、初期と現在が同じ300 mm区間を使用することを確認した。支持Gを実ボタンで+0.001 mm、−0.001 mmと往復し、上段の生値と改善文が操作前へ戻った。旧画像と対応する8状態では、修正前後のYZ生値と局所角度が完全一致した。

短Zの実走査不足（支持奥行0.5 mの保存状態診断用fixture）は測定無効となり、「測定が成立しないため比較できない」を表示する。無効値を0として比較しない。初期記録を持たない理想fixtureも「初期との比較基準なし」であり、仮のゼロを初期値にしない。支持奥行欄は通常UIで隠れているため、この短行程検証だけは実UIクリックとは呼ばず、明示的な状態注入として記録した。

この修正は可視の改善文が別量を混同していた欠陥の修正である。横形YZのtop/Z法とvertical/Y法のどちらがユーザーの求める配置かという未確定事項を、改善文修正で解決済みにしていない。
