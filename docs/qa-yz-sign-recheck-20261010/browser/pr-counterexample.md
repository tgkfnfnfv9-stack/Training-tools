# PR 修正前に残っていた YZ 描画の反例

PR `874d659` の固定 HTML（SHA256 `de228d28fac23cc55b9ff914a29116500e53a1324b90cfd324ec00548132e7dd`）で確認。先のランダム 700 姿勢に反例がなかったことは描画の正しさを意味しない。

理想状態、X/Y/Z = 0、平坦状態から実ブラウザーの支持ボタンだけで次の操作をした。

1. A を選択し、粗調整で「上げる」を 5 回 → A ＋0.050 mm。
2. E を選択し、粗調整で「上げる」を 9 回 → E ＋0.090 mm。
3. 微調整に切り替え「上げる」を 1 回 → E ＋0.091 mm。

他の支持点は 0。全設定は既存 UI の入力範囲内。

|観測|値|
|---|---:|
|YZ 生値|＋0.033566085703 µm|
|別実装の平面・直線交点による期待値|＋0.033566085697 µm|
|整数表示|0 µm|
|始点の測定子伸び|10.000000000000 mm|
|終点の測定子伸び|9.999966433914 mm|
|平坦時の SVG 測定子全長|11|
|操作後の SVG 測定子全長|11.012564337023|
|図の変位・傾きの制限|false|

実際の計器は縮むのに、図では長くなる。丸めや図のクリップを理由にできない。整数が＋と表示される反例ではなく、生値と図の伸縮が逆になる反例。

本体移動の強調倍率と傾きの強調倍率が独立しているため、描いた線分の全長が実際の計器伸びに従わない。二支持の 1 µm 刻み 42 条件で 13 件の反例を得た。巨大な全探索ではなく、寄与が近く打ち消し合って読みに比べて相対傾きが残る条件を探した。
