## 観察事実

1. 小型立形・移動コラム・5軸A=C=0の図はXYが下端0から上端へ、XZ/YZが上端0から下端へ。詳細文はXY＝手前→奥、XZ＝上右→下、YZ＝上奥→下を記す。
2. `horizontal-YZ-live.png` は画面右向きの押込み矢印に「上」、画面下向きの走査矢印に「手前」。`double-XY-live.png` は画面上への走査に「右」、画面右の押込みに「奥」。機械座標への変換は詳細文に存在するが、常設の小図には投影説明がない。物理的に存在しない下送りをこれらに描いているわけではなく、展開した走査を画面上下に配置している。
3. 通常のマスタ図にはR面/S面のラベルが無く、「直角」とL字の黒線だけ。詳細文が説明する方向合わせ面Rと読み比較面Sを図だけでは確定しづらい。旋盤だけSラベルがある。原因：`src/reference-measurement-ui.js:50`以降。
4. 同じ新SVGに旧局所角度図の属性が全19面で残る。例：小型XZの `data-zero-location="左下"` と `data-zero-location-measurement="上・右側"`、旧投影 `1,0,0,1,-5,13` が併存。原因：`src/accuracy-ui.js:271`以降。見えている新図の0は上側だが、DOMを根拠に検証すると旧定義も読めてしまう。
5. 平定盤側面を代用しない旨、R/S直角保証が必要な旨、方向合わせとゼロを状態変更ごとに取り直す旨は既存詳細文に明記されている。ただし、この仮想取付けが全機種で実際に実現可能かはブラウザー再現性試験では証明していない。
6. 図は固定面と計器本体の間隔を有限値に応じて変える。正値では本体が面へ近づき、負値では遠ざかる。押込＋矢印は測定子が本体へ引っ込む向きなので、本体が面へ動く向きと反対になっている。矢印をNC指令や本体移動だと読むと逆になる。明示が必要。

`observations.json`：7機種・19面、30件の状態再現性検査が通過、JS pageerrorなし。

- 全7機種：カメラyaw・zoom・表示誇張を変えても有限走査値、4方向読みは不変。
- 全7機種：支持+0.01mm→-0.01mmで値が戻る。
- 全7機種：実際のJSONダウンロードを取得し、支持とXを変えたあとfile inputで読み込み、値・支持・軸位置が戻る。
- 全7機種：各直線軸の両端を試し、有限値または明示的抑止となる。全端点の状態はJSON内 `checks[].details` に記録。

上記は実装の再現性検査であり、計測配置・符号・機械構造の正しさを意味しない。期待する物理符号を描画関数・符号表から生成する試験は作っていない。独立した幾何オラクル、支持補間境界の連続性、全模型頂点と軸矢印の微分一致、4方向の手前面外時の全表示抑止は本ブラウザー担当では未検証（別担当の検証を参照）。移動端でNaNが出ないことは、測定範囲や接触点が現実に成立する証明ではない。
