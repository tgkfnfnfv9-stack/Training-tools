# 模型運動・軸表示・主軸4方向測定の独立点検

対象 checkout: 127b3ece7da64cab5d1fb9bbb998313d739fd905。親担当が作業開始時 upstream main を確認。ここではアプリを変更していない。既存説明・既存テストの符号を期待値とせず、部材の機械的所有関係から理想方向を別記して模型頂点を調べた。

## 1. 何が＋なのか

内部物理名は app.js:12 の「左右=x、上=y、奥=z」。axisConfig の正ベクトルは **可動部品スライダーを増やす向き**（app.js:16–23）。UI は「部品位置」「片側／反対側」（app.js:550–554）であり、NC指令値／NC正方向という仕様はない。referenceCard だけがこれを「＋X」「−Y」等と呼ぶ（reference-measurement-ui.js:60）。よって NC 指令方向との対応は全機種で明文化不足。特にテーブル軸では計器相対運動と逆になる。

下表の右／奥／上は機械の物理方向で、カメラ投影方向ではない。相対は `計器固定部−基準器固定部`。旋盤だけは計器が刃物台、基準器が主軸なので tool/work の内部変数名を人間の工具／工作物と取り違えてはいけない。

|機種|スライダー増分|実際に動く部材と向き|計器の基準器に対する相対移動|基準器／計器の取付候補|
|---|---|---|---|---|
|小型立形|X / Y / Z|テーブル右 / サドル＋テーブル奥 / 主軸頭上|左 / 手前 / 上|テーブルの直角マスタ／主軸頭のブラケット|
|横形|X / Y / Z|コラム右 / 主軸頭上 / パレット奥|右 / 上 / 手前|パレットの直角マスタ／主軸頭のブラケット|
|移動コラム|X / Y / Z|コラム右 / 頭のスライド奥 / 主軸頭上|右 / 奥 / 上|固定テーブルの直角マスタ／主軸頭のブラケット|
|固定門形|X / Y / Z|テーブル奥 / サドル右 / ラム上|手前 / 右 / 上|テーブルの直角マスタ／ラムのブラケット|
|移動門形|X / Y / Z|門一式奥 / サドル右 / ラム上|奥 / 右 / 上|固定テーブルの直角マスタ／ラムのブラケット|
|5軸 A=C=0|X / Y / Z|トラニオン右 / サドル奥 / 主軸頭上|左 / 手前 / 上|旋回テーブルの直角マスタ／主軸頭のブラケット|
|旋盤|X / Z|刃物台奥 / 往復台右|奥 / 右|主軸フランジ／刃物台のブラケット|

機械構造の根拠: app.js:259–287。旋盤刃物台は z=-.58（手前）で、X増分は主軸中心 z=0 に近づく。通常の外径NC +X（中心から離れる）と逆なので、この部材スライダーをそのままNC +Xと説明してはいけない。Z増分は主軸台の右へ離れる。Xの直径指令／半径実移動の倍率も未定義であり新規導入すべきではない。

取付候補の表は「機構として可能な組合せ」であり、ブラケット寸法・接触高さ・干渉・ストロークを確認した実在装置の取付図ではない。現在アプリに固定具の実座標はない。

## 2. 軸矢印と模型

- 模型上の直線・旋回矢印は **両端矢印**（app.js:451–456）。「正方向」そのものを示していない。Cの曲線点列は slider C の回転と逆順だが、両矢印なのでこれは単独では不一致ではない。
- 左の向き目安は a.vector をカメラ角で投影した単矢印（app.js:391–405）。これは名目スライダー増分方向で、支持変形・固有角度は意図して含めない。模型に重ねる矢印と役割が違う。
- 理想状態の37可動グループに対し、部材所有関係から手で定義した期待方向と実模型頂点の微小変位が一致。`kinematics-probe.cjs/json`。axisConfigや描画関数から期待方向を生成していない。
- 非一様支持面で可動部姿勢が変わると、各頂点は並進＋回転の運動となる。一つの代表案内矢印が全頂点の瞬間移動を表すわけではない（app.js:64–75）。従って「全頂点と矢印が常時平行」を正解にするとかえって誤る。非理想状態の全頂点の網羅検証は本担当では未実施。
- カメラだけの投影は app.js:383–389、数値は別経路。画面右を常に機械右とする根拠はない。

## 3. 有限走査と模型の材料点運動の反例

横形XZ、固有誤差なし、全軸中央、支持値(mm)
`[.2,-.2,.06666666666666668,-.06666666666666668,-.06666666666666667,.06666666666666667,-.2,.2]`。

Z部材 0→300 mm に対し、referenceScan は始点以降の代表Z方向を積分（reference-measurement-ui.js:37）し、基準面原点変位を `[0,0,.3] m`、読みをほぼ `0 µm` とする。一方、パレット上面中心 raw `[0,1.27,-.85]` を物体の同じ材料点として追跡すると、factor=1で変位は `[-14.625959 µm, +0.000818 µm, 300 mm]`。基準面搭載高さ0.61 mの姿勢変化による横変位が入る。

同材料点をマスタの原点と仮定し、同じ初期方向合わせ・法線輸送のまま直線と平面の交点を独立に求めると `−14.625959 µm`。検証式は `λ = n·(P−B)/(n·p)`、読みは `(λ0−λ1)10^6`。保存した `material-point-probe.cjs/json` で再現できる。

これは「必ず−14.625959へ直せ」という提案ではない。現在はマスタ高さ・取付原点が未定義なので、模型パレット搭載の有限実測と代表方向積分を同じ量として扱えないことの反例。計算修正には固定具原点と剛体輸送の仕様を先に決める必要がある。現行5軸は3点支持で平面を作るため、A=C=0で同様の反例は今回得られなかった（同スクリプト）。小型立形Yは別途 compactTablePathPoint を使用している（同37行）、その配慮が横形へ一般化されていない。

修正案の概念図:

```
現在:   支持位置 O ── 代表案内方向を積分 ── O'
                          ↑ 仮想接触原点と同一視
候補:   支持位置 O ── 並進＋姿勢変化 ── O'
        マスタ点 P=O+R h             P'=O'+R' h
        読みは P,P' と計器 B,B' の相対配置から求める
```

共通剛体変換に対する不変性だけではこの高さ省略は検出できない。姿勢が経路中に変化し、取付オフセット h≠0 の試験が必要。

## 4. Z送りと主軸中心線

`intrinsicBodyFrame`（accuracy-ui.js:13–23）は鉛直を向くNC軸を優先して代表剛体姿勢を作る。小型立形・移動コラム・門形・5軸はZを選び、横形はYを選ぶ。旋盤は鉛直軸がなくZを選ぶ。

- 立形系5種の主軸中心線は tool支持姿勢 × Z由来代表固有姿勢。4方向測定もこれを使用（spindle-sweep-ui.js:14,104）。独立の主軸傾き誤差パラメータはない。「この教材では同じ方向へ結び付けている」であり、実機でZ送りと主軸中心線が必ず一致するという事実ではない。
- 横形の実模型主軸は z向き円柱（app.js:277）をY由来の剛体姿勢で回す。Z送りは work側パレットの方向であり、Y由来の主軸中心線と別。`bodyCombinedDirection`自体はこの機種で鉛直Y代表線なので、横形主軸中心線として使ってはならない。現4方向測定は横形を対象外にしており、その点は適切。
- 旋盤は局所XZのZを主軸支持 tool方向として保持（accuracy-ui.js:107–109）、往復台Z実移動はwork側姿勢を使用（leveling-ui.js:112、app.js:371）。既存「主軸基準XZ」は往復台Z送りの真直度／平行度検査ではない。Y軸を追加する理由はない。
- 門形主軸メッシュは portalZVisualPoint で代表Z線へ向きを合わせる（app.js:82–103）。これは測定値を変えない描画変換。独立した主軸傾きとZ送り誤差を新設するなら計算モデル変更・保存互換性検討が必要で、今回点検の許可だけでは導入不可。

## 5. 既存4方向ダイヤル（別検査）

|機種|適用と注意|
|---|---|
|小型立形|テーブル上面に対する主軸旋回。P経路、テーブル上面法線、面外チェックあり|
|移動コラム|固定テーブルに対して頭から旋回。模型主軸／テーブル位置のfactor1変換を使用|
|固定門形|可動テーブルに対してラム主軸から旋回。門のshearと代表主軸線を使用|
|移動門形|固定テーブルに対して移動門のラムから旋回|
|5軸|A=C=0は通常の上面掃引。A/C≠0も傾斜上面との交点を計算する別姿勢の測定で、XYZ直線軸直角度検査と同一ではない|
|横形・旋盤|現行非対応、追加不要|

`spindle-sweep-ui.js:6`で5種限定。`spindle-sweep.js:35–67`は主軸直角平面の半径150 mm円を各角度から主軸方向へ投影し、テーブルとの交点高さを手前基準にしている。0/90/180/270度=右/奥/左/手前。方向は画面ではなく主軸・機械に付随する右/奥で、カメラ回転では変わらない。

独立の平面 `y=kx+mz` と鉛直主軸から手計算した期待値は `[r(k+m),2rm,r(-k+m),0]×10^6 µm`。k=100 µrad,m=200 µrad,r=.15 mなら `[45,60,15,0] µm`、符号逆の平面では `[-45,-60,-15,0]`。理想0と合わせ実エンジン一致（kinematics-probe.json）。正は固定円に対して上面が高くなり測定子が押される向き。＋軸とは別。

手前が面外なら全数値を抑止（spindle-sweep-ui.js:130–141）。個別面外も抑止。5軸傾斜姿勢は平面との交差角・面外を考慮するが、実際の測定子伸縮限界、ブラケット干渉、テーブル上のワーク干渉を再現していない。測定子は模型ワークが存在してもテーブル上面へ接触できる仮想条件。これをそのまま現場の計器設置可能性の保証としない。

主軸4点法は主軸回転中心線と上面の相対傾きを測り、Z送り軸と上面の直角度を直接測るものではない。教材が主軸線をZ由来代表線に結び付けているため相関して見える。

## 6. 変更範囲案

表示のみで可能: 部材スライダーの符号とNC指令を区別する文言、両矢印/名目向き目安の説明、機種ごとの実方向と展開図の対応、主軸掃引と直線軸測定の区別。既存UIに大見出しや丸ダイヤルを加える必要なし。保存JSON変更なし。

計算承認が必要: マスタ取付位置・高さと計器原点を具体化し、全剛体変位を有限測定へ使用すること。固定具パラメータを新設する場合は表示測定の仕様IDと保存方針の検討が必要。現在保存は levelRecord（leveling-ui.js:27）の支持・個体・軸位置を持ち、reference scan測定値を保存していないため既存支持値を破棄する理由はない。ただしロード後の表示値再計算は変わる旨を明示する必要がある。局所角度計算・支持最適化・固有誤差は維持すべき。

未確認: 全機種の実在測定器取付寸法と干渉、全支持境界における全材料点の微分連続性、A/C姿勢の実計器ストローク、NCメーカー固有規約。ブラウザー画像は親担当が別採取。
