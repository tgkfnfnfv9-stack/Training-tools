## 所有先と測定方向

|項目|基準器|計器|測定走査|
|---|---|---|---|
|XY|テーブル上の直角マスタ|主軸側固定|主軸頭Y＋、下→上|
|XZ|テーブル上の直角マスタ|主軸側固定|テーブルZ＋、計器の相対移動は手前|
|YZ・変更後|テーブル上の直角マスタの主軸側縦面|主軸側固定|主軸頭Y＋、下→上|
|Z平行度a/b|主軸固定テストバー|テーブル固定|テーブルZ＋、バーは固定|

YZのR合わせは、主軸側計器を上面へ当てて止め、テーブルをZへ300 mm送り、両端を等指示にする。同時に、R両端の測定子が厚み50 mmの中央線を通るよう横方向も合わせる。マスタを固定したまま選択Z位置へ戻し、S用の腕へ付け替え、Y区間下側でゼロ。SのY走査中はテーブルとマスタを固定する。

各操作で返されたR始終点、両端等指示、選択Zへの戻し、S始終姿勢、初期伸び10 mmを確認。図は「上＝Y上」「右＝Z奥」、Rは上面、ゼロは下、走査矢印は上。取付先表示・カード・読み上げ用ARIA・共通走査説明も同じ配置になった。

## 実操作と独立期待

理想／used seed123456、B/E/G/H各±0.010 mm、Z−100でG/H同時±0.010 mm、全3軸の両端、支持往復を採取。61状態。初期プロファイルと平坦状態は既知入力として設定し、その後の支持ボタン・軸スライダーは実ブラウザー操作。PC1280×1000、携帯幅390×844で表示を確認した。

単に読みの符号を反転した値ではない。配置・基準合わせ・計器の相対運動を変えて接触から読み直している。

**全61状態のYZが、支持・保存された個体差・軸位置から組み立てた独立3D期待と一致**。最大差3.11×10⁻¹⁰ µm。独立3D計算では製品の姿勢・走査・接触関数を期待値に使っていない。これとは別に、左右同高・理想の21状態を独立YZ断面計算でも照合した。初回の断面検証だけでは非対称・used40状態を覆っていなかったが、後続3D検証で全61状態を確認した。

XY/XZ/YZは捕捉した面と測定子の別の交点計算、a/bは円筒までの符号付き距離を二分探索する別計算でも照合。全305値で一致、最大差4.03×10⁻¹⁰ µm。整数は `sign(raw) × round(abs(raw))` とDOMを照合した。**同じ入力に対するXY/XZ/a/bの生値と整数は、修正前後の全244値で完全一致**。支持操作中にこれらが常に一定という意味ではない。

## カード撮影の訂正

初回の `locator.screenshot` は、約1,000〜1,400 pxのカード全長を、約152〜157 pxのスクロール窓を持つ親の外まで撮ろうとしていた。その結果、空白や別の画面領域を含む画像になった。製品カードが空白になる不具合ではなく、撮影範囲の誤りだった。

スタイルを変更せず、実際のスクロール窓・カード・ブラウザー表示領域の交差だけを連続スクロール位置ごとに撮り直した。各画像の矩形・scrollTopは最終スモークJSONに保存。先頭から末尾まで実内容を確認した。誤った4枚は [superseded-capture-artifacts](superseded-capture-artifacts/) に隔離し、製品表示の証拠として使わない。

再実行：`tests/browser-horizontal-fixture-20261010.cjs`、`tests/join-horizontal-fixture-browser-20261010.cjs`、`tests/browser-horizontal-fixture-final-20261010.cjs`。Linux Chromiumでの確認。携帯幅はエミュレーションで、実iPhone Safari・実機は未確認。
