# 構造・物理挙動の点検（2026-10-06）

後続修正：小型立形の表示を、同時点のサドル姿勢からテーブル上面Pの送り角へ変更した。本書の小型立形XY不変という旧モデルの説明は、現在のPの送り角には適用しない。共通回転の分離も小型立形へ追加した。最新の根拠と限界は [compact-table-path-20261006.md](compact-table-path-20261006.md) を参照。

点検開始時の main：`0bbd020e340695a2aee9333a1f2d2920e0ac02cb`。対象は既存の全7機種。機種・支持点数は変更しない。固定門形は長手ベッド9点と左右柱各3点の教材用15点を維持する。

この点検は、支持調整と模型・軸方向・比較図の幾何的な整合性を確認するもの。ユーザーが明確化した目標は「柱下の調整によって前後・左右の倒れが生じ、その姿勢に関わる精度の変化を理解すること」であり、実機の応答量の定量再現ではない。実機の剛性値、支点反力、アンカー締付け、接触状態を同定した構造解析や、メーカーの検査合格を意味しない。数値は教材モデル内の量で、実機の調整量に換算して使用できない。

## 3. 変更前コードで見つかった問題

1. **柱と梁の接続に使う情報が違った。** `geometryModel` は左右柱の局所勾配を別々に模型へ与え、梁・工具には勾配の平均を与えていた。柱天端の実際の位置を梁端に拘束していなかった。
2. **梁の水平ヨーが欠けていた。** 左右柱の前後倒れが違えば天端間の前後差が生じるが、2方向勾配の平均だけでは梁横方向の水平ヨーを表せない。XYに一次的に伝わる幾何的経路が欠ける。
3. **不規則な全15点補間を部位の姿勢へ直接割り当てていた。** 遠いベッド点を変えても柱下の微分が変わるが、その伝達は薄板スプラインの数学的性質であり鋳物の剛性ではない。ベッドと柱の支持を区別しにくかった。
4. **部品の姿勢とNC案内方向を二分類だけで兼用していた。** 移動コラム・移動門形のXが固定テーブル側を、旋盤Zが主軸台を参照していた。とくに旋盤ではNCのXZ直角と主軸軸線に対するX方向の比較が混在していた。
5. **門形の結合モデルでは、共通姿勢と相対変形を明示的に分ける必要があった。** 局所の総勾配ごとに別々の回転を作る方式と、共通剛体回転の下で柱・梁を組み立てる方式では高次の項が異なる。なお、非平面の支持高さに同じ平面勾配を足すことは、水平座標まで変換する厳密な剛体回転と同義ではない。したがって、そのときの高次差を全機種共通のバグとは扱わない。

これらは修正可能な幾何モデル・表示定義の問題である。剛性・荷重・支持接触などの未確認事項とは分ける。

## 4. 教材モデルの採用方針

構造担当と修正担当で、次の幾何的な方針を合意した。実装と検証の最終結果は [verification.md](verification.md) を参照する。

- 門形の結合計算では、支持高さを平均平面と残差へ分ける。共通の平行移動・回転は門形の全ての軸へ同じ変換を適用し、部位間の角度に混入させない。他の機種は総局所勾配から直交姿勢を作る方式を維持し、一様高さ移動と純平面状態で内部直角が変わらないことを確認する。
- 固定門形はベッド9点と各柱3点を分けて姿勢を作る。各柱の3点は一直線ではないため、前後勾配と内外勾配を区別できる。
- 固定門形の模型・支持面表示も部位別の構造面を使う。従来の全15点薄板スプライン面を、柱・ベッドを一体にした実物の変形として表示しない。全支持の従来補間は元の支持解析・評価用データに残るが、局所部品姿勢の直接の根拠とは分ける。
- ベッドと柱側張り出しの表示を突然切り替えると人工的な段差ができるため、実支持点を避けた接続領域で高さと勾配を滑らかにつなぐ。これは幾何的な接続用補間であり、実機の応力・たわみ分布ではない。
- 左右柱の足元と姿勢から天端位置を求め、その天端を結ぶ方向を梁のY方向に使用する。梁端と柱天端の接続を模型と計算で共用する。
- 梁Yは柱天端間の方向、ラムZは左右柱の上方向の等重み平均を使い、両者を直交させない。奥行方向はYとZの外積で定め、一つの一定アフィン変換として模型・移動・軸方向を共用する。Xとの相対角は、梁とテーブル／走行案内の相対姿勢から求める。XYやYZを操作名だけで悪化させる分岐は入れない。
- NC送り方向の所属と、主軸軸線・コラムの姿勢を区別する。模型の部品姿勢を変える処理と精度比較の定義を揃える。
- 固有誤差を保持する。支持誤差との相殺で一位置の一項目が良くなることはあり得るが、固有誤差自体を支持調整で書き換えない。

ここでの「結合」は、柱天端中心と梁側の対応する中心位置が一致する幾何的な結合である。接続を閉じるため梁の長さの微小変化と断面のせん断を許す。端面の回転角まで連続させる構造拘束、実機の柱と梁の締結剛性、反力、曲げ・ねじり・弾性せん断剛性、梁長手に沿うねじれ分布は解かない。門形骨格と固有直角誤差は分離し、固有誤差は軸矢印・直角図に示す。

以前の直交梁モデルではY/Zを必ず直交させていたため、柱の左右倒れがYZへ伝わらなかった。今回の `portal-shear-v2` ではZ方向をYに直交化せず、柱の平均左右倒れや左右高さ差がYZへ、前後倒れがXZへ、左右の前後倒れ差が梁Yのヨーを介してXYへ伝わり得る。初期誤差との相殺で改善も悪化もあり、左右の変化が相殺されれば変わらない項目もある。

左右柱の重みは常に1/2ずつなので、Y移動だけで梁・ラムの姿勢は変わらない。Y/Z位置による荷重たわみも再現しない。位置比較が扱うのは固定門形のテーブルXに伴うベッド局所姿勢、移動門形のX走行位置に伴う左右レール姿勢である。Haas資料の梁ねじれ測定結果まで再現したとは扱わない。

固定門形の柱側3点はベッドと独立した座面姿勢を与える。一方、移動門形の既存2列格子では左右の横勾配が同じになるため、左右柱の平均方向と天端間方向の直交が維持され、YZが変わらない場合がある。これを不具合として角度を強制的に変える処理は入れない。

## 5. 独立した検証基準

期待値は現在の表示値から生成せず、以下の幾何的制約で作る。

- 正規化した軸ベクトルの内積から直角差を求める。任意の共通剛体回転は内積を保存する。
- 全支持同量上下は平行移動であり、局所傾斜・ねじれ・内部直角差を変えない。
- 同じ剛体へ同じ回転を与えた軸対は、もとの固有直角差を保存する。門形の梁YとラムZは今回せん断を許す別方向として扱うため、両者の角度を剛体不変条件で固定しない。
- 柱3点の平面は独立した連立方程式から求められる。前後2点の差と内外点の差を別々に比較する。
- 梁の横方向は左右接続点の差ベクトルと平行でなければならない。
- 支持操作を逆操作で戻すと、全モデル状態が再現される。保存・読込や表示操作でも計算状態が変わらない。
- 移動する案内部は位置に対応した支持姿勢を使う。機構上位置が変わらない部位へ、軸名だけを理由に姿勢変化を追加しない。

微小なXYZ全体移動、共通傾き、初期固有誤差、表示誇張はそれぞれ別のものとして検証する。スマートフォン寸法のブラウザー検証は実機の指操作検証と同一ではない。

## 6. 構造確認担当による門形修正後の再点検（7047a65までの記録）

修正コードを担当者とは別に確認し、実画面更新が部位別モデルを通らず旧補間を直接使用していた経路を検出した。`updateLeveling` が評価処理と同じ `machineSolution` を使うよう修正されたことを再確認した。

柱脚と柱座、柱天端と梁端は共通点として一致する。初期の修正案にあったベッド／張り出しの表示境界の段差は、接続領域の滑らかな補間とベース面分割で解消した。

- `tests/check-structural-connections.cjs`：290検証成功。固定・移動門形、一様上昇、左右片側、前後差、ベッド側、誇張の有無を比較。柱／梁接続差の最大値は浮動小数点丸めの範囲（4.45×10⁻¹⁶未満）、柱脚／座面は0。接続領域を挟む極近傍で位置が連続し、15支持点の高さも保持。
- `tests/check-accuracy-review.cjs`：75検証成功。移動コラムは移動位置で姿勢が変わっても、同じ局所剛体姿勢を用いるX/Zの直角が変わらないことを独立した直交不変条件で確認。旋盤の比較図は「主軸基準XZ」であり「NC送りX–Zの案内直角度ではない」ことを表示で区別。

上記は幾何と表示の一貫性を検証した結果であり、HaasやHwacheonの実機応答との定量一致を証明してはいない。

### 追加確認：柱倒れとYZの関連

ユーザーが目標を明確化した後、梁YとラムZを直交化していた処理を一定の非直交変換へ変更した。構造担当が別途、誇張なしの模型のY/Z方向を座標差から求め、内積で角度を再計算して精度値と比較した。固定・移動門形の4操作ずつで模型と角度、実際のY/Z移動方向の24確認が成功し、角度差の最大は3.4×10⁻⁹ µrad未満だった。柱脚・梁接続の290検証と既存の独立レビュー75検証も再実行して成功した。

これにより固定門形では、左右倒れの成分がある支持操作で模型の断面角とYZが一緒に変化する。前後差・ベッド側だけなど成分が異なる操作は、それぞれ関係する軸対に伝わり、関係のない軸対を無条件には変えない。門形2機種の計算仕様を `portal-shear-v2` として旧計算仕様の保存から分け、この時点ではその他5機種は `connected-frames-v1` を維持した。後続の4機種の変更は次節に記載する。

## 7. 全機種の追加点検：案内部位と移動する参照

追加作業開始時のmainは `7047a65`。既存の門形せん断モデルを維持し、「ねじれやコラム倒れと関係する精度が自然に変わる」という目標で、残る5機種の参照を再点検した。全ての操作で全ての直角差が動くことは要件にしない。

### 確認した事実と、追加する仮定

[Mazak VTC公式](https://www.mazak.com/us-en/products/vtc/)は固定テーブル・移動コラム構成を示す。[Haas VS据付](https://www.haascnc.com/service/troubleshooting-and-how-to/how-to/vs-series---installation---ngc.html)はコラムベースとテーブルベースの水準・相互直角を別々に確認し、結合締付け後に再検査する。後者は本教材と移動構成が異なるため、本教材の参照位置や応答量を保証する資料ではない。

移動コラム・横形のX走行案内とコラム根元を別の局所姿勢とする変更は、部位構成に基づく**幾何的な取付ベース変形の仮定**である。2本のレール位置とコラム代表位置は既存の描画寸法を使う。案内ブロックの有限面接触や足元全域の剛体適合、取付ボルト剛性、反力、荷重たわみは解かない。メーカーが特定の支点調整でこの量だけ倒れると示したわけではない。

|---|---|---|
|小型立形|Xテーブル移動で、その下のYサドルの支持参照までX移動していた。参照xを0に固定し、Yだけ追従させる|XYは同じサドル姿勢で不変。X重量移動によるたわみは未計算なので、X操作だけの姿勢変化は発生させない|
|横形|X走行案内とYコラムを同じ姿勢で扱っていた。Xは描画2レール `z=D*0.28±0.13` の平均勾配、Yは柱根元 `z=D*0.29+配置差` とする|XYへ相対姿勢が伝わり得るが、参照差 `0.01D` を感度目的で増幅しない。水平軸間XZは水平ヨーなしでは変化がないか小さな高次変化となる場合がある|
|移動コラム|全XYZが同じ姿勢で、案内と柱取付部を区別できなかった。Xは描画2レール `z=D*0.22±0.1`、Y/Zは柱根元 `z=D*0.29+配置差` を使う|XZへ柱倒れとの差が伝わり得る。XYは方向成分があれば変わるが、全軸対の変化を強制しない。YZは同じ剛体コラムで不変|
|固定門形|15点と非直交の結合モデルを維持|梁のY/Z移動による荷重たわみ・ねじれ分布は未再現|
|移動門形|左右走行位置と非直交の結合モデルを維持|既存2列格子ではYZ不変となる幾何的相殺があり得る|
|5軸|3点支持の共通平面モデルを維持|支持調整は全体を回し内部XYZ角を変えない。A/Cの荷重変形・回転軸精度は対象外|
|旋盤|X径送りで往復台のベッド参照まで前後へ移動していた。描画往復台中心 `z=-0.15` に固定し、Z長手移動だけを反映|主軸基準XZは水平軸同士の比較で、ベッドの鉛直ねじれの全てがその角度に現れるわけではない。主軸平行度・刃物高さ・実切削テーパは別の未再現量|

小型立形と旋盤は、描画親部品の移動と計算参照が一致していなかった問題の修正。横形と移動コラムは、区別していなかった案内と柱取付部を分ける教材モデルの改善である。後者の実機応答量は未確認のままである。高さだけの面から独立した水平ヨーを作らず、数値を動かすための乱数・支点別の強制角度・経験係数は加えない。

計算意味が変わる4機種は `compact-saddle-v2` / `horizontal-guide-v2` / `travel-guide-v2` / `lathe-carriage-v2` に分ける。旧保存は削除も無言の再解釈もせず、旧仕様として保持する。5軸 `connected-frames-v1` と門形2機種 `portal-shear-v2` はそのまま使用する。

### 構造担当の追加再確認

修正担当とは別に、横形・移動コラムについて純ねじれ、共通平面、単一支持上げとX位置の手前・中央・奥を組み合わせて54項目を確認した。誇張なしの模型で、柱の上下2点の差から得た方向は精度計算のY（横形）／Z（移動コラム）と一致し、ベクトル差の最大は `1.55×10^-16`。柱足元の代表中心とベッド面が一致し、描画2レールの有限差分接線の平均も計算X方向と一致した。

ここで一致を確認したのは代表方向と中心の接続であり、柱足元の全面・全案内ブロックを同時に接触させる適合条件ではない。その拘束を解かない限界は残る。全7機種の操作・保存・画面を含む最終検証は [verification.md](verification.md) を参照。
