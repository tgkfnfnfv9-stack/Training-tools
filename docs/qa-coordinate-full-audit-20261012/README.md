## 座標系と変換（全機種共通、確認済み）

| 区分 | 定義 | 根拠 |
|---|---|---|
| 内部xyz（描画・計算） | x＝右、y＝上、z＝奥。単位は m | app.js:12 |
| 機械XYZ | 機種ごとに割り当てる（小型・門形2機種：X左右/前後…、横形：Y上下・Z前後、旋盤：X＝内部z、Z＝内部x） | app.js:15-23 |
| 支持座標 | `levelCoordinates`＝生の座標×(width/(w×0.8))。標準寸法では等倍 | leveling-ui.js:53 |
| 支持高さ→面 | 高さは mm、勾配は mm/m（計算では/1000）。3点＝平面、格子＝双一次、小型＝平面＋ねじれ＋2モード板曲げ、L3＝ベッドと柱を別の面に分ける | leveling.js, machine-accuracy-ui.js:19- |
| 部材姿勢 | 共通平面の回転∘局所の残差回転∘固有方向（純粋な回転）。並進は「回転後の座の点＋回転した相対ベクトル」 | accuracy-ui.js:55-118 |
| 接触 | 伸び e＝n·(P−B)/(n·p)。指示＝(e₀−e)×1e6 µm、＋は押込み増加。有効範囲は0〜20 mm と面の範囲 | reference-measurement.js:5-17 |
| 整数表示 | 絶対値を四捨五入して符号を付ける。0は符号なし | accuracy-ui.js:273-276 |

- `Leveling.orientation` は内部基底の上では右手系です。z＝奥を実空間に置くと見かけは左手系になり、機械XYZは X×Y＝−Z になります。回転と符号の誤りは見つかっていません（共通担当）。
- **共通の剛体の傾き**（全支持を一つの平面で傾ける）では、直角3枠・触れ・Z平行・旋盤検査の値はまったく変わりません。変わるのは重力を基準にした「倒れ」表示だけで、物理的に正しい動きです（全機種、独立検算済み）。

## 3種類の値の区別

| 値 | 中身 | 画面 |
|---|---|---|
| 局所角度の300 mm換算 | その軸位置での2方向の角度差 −asin(â·b̂)×0.3。＋は90°より開く向き | 設定内の図。数値の欄（評価長500 mm）は hidden のカード内 |
| 有限区間走査 | 300 mm を送り、始点でゼロを取ったときの終点の相対接触。＋は押込み | 主画面のXY/XZ/YZ 3枠 |
| 主軸旋回（触れ） | 主軸に付けた計器を半径0.15 m で旋回させ、テーブル面に当てる。手前でゼロ | 主画面の触れ4方向（小型・移動コラム・門形2機種） |

- XZ・YZ・旋盤XZでは、局所角度（＋＝開く）と走査値（＋＝押込み）の符号が逆になります。定義の違いであり誤りではありませんが、混同しやすい点です。
- 小型Y・横形Z・横形のR合わせ以外では、有限走査の値は「始点1点の局所角度×0.3」と同じになります（reference-measurement-ui.js:139, 149）。「局所角度換算とは別の値」という説明は、移動コラム・門形2機種では中身として成り立っていません。

## ゼロ条件（全機種共通の結論）

- **製品が表示しているのは条件Bだけです。** 支持・軸位置・寸法が変わるたびに、裏で方向合わせと始点ゼロを取り直しています。
  - 直角3枠、横形Z平行a/b、旋盤の刃物台X/Z・テストバー：B
  - 触れ：手前で再ゼロ（C相当）
  - 旋盤の穴芯：aで再ゼロ（C相当）
- **条件A（取付と最初のゼロを保持）は、製品に機能も表示もありません。**
- 独立確認でA・B・Cを別々に計算すると、AはBと大きく異なりました。**画面の値を「器具を付けたまま支持を回したときの針」と読むことはできません。**
  - 例：横形、中央4本＋0.05 mm の YZ は A −130 ／ C −75 ／ B −79（製品 −79）µm。
  - 例：小型、P1 −0.2 mm の XY は A −54.9 ／ B −38.2 µm。
- Aを求められるかどうかは機種と項目で異なります。

| 機種・項目 | 条件Aの判定 | 理由 |
|---|---|---|
| 横形 直角XY/XZ/YZ・Z平行 | 製品の治具の定義の範囲でなら計算可能（独立確認が計算済み）。ただし腕の長さ約1.25 m などはユーザー未指定の仮定 | 製品に腕（bracket）とマスタの寸法が定義されている |
| 小型 直角3枠 | **条件不足** | XZ/YZのマスタの位置と腕の取付点が未定義。XYの接触点Pだけが定義 |
| 移動コラム・門形2機種 直角3枠 | **条件不足** | S面の点が世界原点の抽象点で（ref-ui:147）、マスタのテーブル上の位置と腕が未定義。走査中の増分だけは計算でき、Bと最大約39 µm 違う |
| 触れ（4機種） | 剛体の仮定で4方向が同じ量だけずれる（移動コラム +24.09、門形 +82.52、ガントリー −1.69 µm）。測定子のストロークは未定義 | 手前の接触点の移動 |
| 旋盤 刃物台X/Z・バー・穴芯 | 製品の剛体の仮定の下でなら計算可能 | — |
| 旋盤 主軸基準XZ（フランジ） | **条件不足** | 接触点が原点の代表点で、計器の取付位置がない |

Aを、再ゼロ後の値（B）で代用したことはありません。

## 判断できること・できないこと（主軸側とテーブル側の相対関係）

- **触れ（主軸旋回）で分かるのは**、その軸位置での「主軸回転軸とテーブル上面法線の相対的な傾き（2成分）」だけです。手前ゼロのとき、全ケースで「奥＝右＋左」が成り立ちます。
- **単独では判別できないもの**
  - コラムの倒れとテーブルの傾き：相対量しか出ず、共通の傾きは消えます。絶対値には水準器が必要です。
  - 主軸軸線の傾きとZ案内の倒れ：全機種の模型で同じベクトルとして扱っているので、そもそも区別がありません。分けるにはZ送りによる走査（XZ/YZ）との比較が必要です。
  - 固有の直角差と支持による傾き。
- 小型・移動コラム・ガントリーでは、模型の上で「触れの右−左＝XZ走査」「奥−手前＝YZ走査」が±0.01 µm で一致します。主軸軸線＝Z送り方向という仮定によるもので、実機では一致するとは限りません。
- 画面の「コラムの倒れ」は重力を基準にした絶対姿勢で、固有のXZ/YZ差をすべてコラム側に割り当てています（模型の仮定）。ダイヤルの測定では単独に判別できません。

## 計算変更の候補（変更前の説明。今回は src を変更していません）

### 1. 小型立形の `compactMeasurementResponseGain=5` を物理姿勢（1）に戻す ― 実施するか要確認

- **旧式の誤り**：直角YZと触れ4方向を、主軸頭の物理姿勢ではなく、中央の支持由来YZ角δの4倍を足した仮想姿勢で計算しています（accuracy-ui.js:179-223、reference-measurement-ui.js:167-171、spindle-sweep-ui.js:86-88）。ダイヤルが取付先の主軸頭の姿勢に従っていないので、ユーザー指定の「主軸頭が動けばダイヤルも取付先と一緒に動く」と矛盾します。中央以外では比例さえしないので、教材としての「拡大」の説明も成り立ちません。
- **変更する式**：`compactMeasurementGeometry` で回転を使わない（gain=1）。`referenceDisplayScan` と `spindleSweepGeometry(...,teaching=true)` が物理姿勢を使うようにします。新しい補正は入れません。
- **ゼロ条件**：変わりません（B、触れは手前で再ゼロ）。
- **保存データ**：測定値は保存されないため、`compact-asymmetric-bending-v4` の変更や移行は不要です。DOM属性 `data-reading-model`・`data-support-response-gain` の値と、倍率を前提とした既存テスト（tests/check-coupled-yz-sweep-independent.cjs など）は見直しが必要です。
- **経緯**：この倍率は ceb0cba（2026-10-07）で、「YZの支持変化を見やすくしつつ触れと連動させる」教材上の規則として追加されたものです（docs/coupled-yz-sweep-20261007.md）。今回の指定「数字を無理に変える倍率を入れない」と衝突するため、どちらを採るかはユーザーの判断事項です。

### 2. 移動コラム・門形2機種のR合わせを、X実走（300 mm）による方向合わせにする ― 条件不足

### 3. その他（式ではなく、定義・表示の意味の問題）
