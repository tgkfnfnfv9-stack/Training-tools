# コラム前後倒れ拡大表示：独立ブラウザー確認

製品実装担当とは別の担当が、実模型のコラム上下頂点を直接読み、拡大図と比較した。計算や製品ソースは編集していない。

検査スクリプト：`tests/browser-visible-column-lean.cjs`。前版29件、最終追加表示版88件を確認、全件成功。生成HTMLのSHA-256は `faa69d002eaa17741c08e9738e85cef14e5d59d90035999183ac778ce181bf9c`。結果JSONにも記録。

## 独立期待値

支持高さを `h=b z` mm（zはm）と置くと、上向き法線は `(0,1,-b/1000)`。床基準で前倒れを正にした角度は `atan(b/1000)` rad。b=+0.4／0／−0.4を設定し、実模型の柱頂点から求めた角度がこの解析値と一致することを確認した。前倒れは側面図の左（手前）へ、後ろ倒れは右（奥）へ倒れる。拡大図のdata属性だけでなく、SVG変換後の柱上端の座標でも方向を確認。

PC 1280×900および携帯390×844の同じ3状態で、図が前→鉛直→後へ変わることを画像で確認した。この共通傾斜では各軸の相対角は変化せず、XYZの有限測定値は0のまま。拡大図は床基準の姿勢を表し、YZのダイヤルではない。

## 確認結果

- 2000倍の図角が実模型から独立に求めた柱角に一致。
- 支持A単独−0.5／0／+0.5 mmと固有XY=33、XZ=75、YZ=−15を含む11状態で、前後版の支持値・柱頂点・測定値・保存レコードが完全一致。
- 粗0.01／微0.001 mmの実ボタン操作で支持値・物理柱角・拡大図が同時更新。
- X／Y／Z送りで固定柱および前後倒れ図は不動。カメラ・ズーム・ラベル・直角図強調操作で測定値は不変。
- 有効なJSON保存レコードを再読込し、支持値・測定値・柱頂点・拡大図を再現。
- 極端な支持寸法で±65°に制限する場合は「図の範囲外」と表示。
- 他6機種で新しい図を非表示にし、その高さも0。
- 携帯320×568でも図と模型の領域は重ならず、模型canvasは100px以上、上下操作ボタンは画面内。支持選択行の既存の隠れを発見して修正担当へ返し、追加修正後に再確認。320×568と320×480でA-D各44pxボタンの上端・中央・下端が実際に操作可能であることを `elementFromPoint` でも確認。
- ブラウザー例外なし。

## 限界と既存事項

- 粗0.01 mmのA単独1回では実角約1.931 µrad、拡大図の上端変位は約0.21px。微0.001 mmでは約0.193 µrad、上端約0.021px。0.1 µrad表示は更新するが、1回ごとに輪郭が肉眼で大きく動くとまではいえない。±400 µrad程度の前後比較では約±45.8°となり、明瞭に見える。
- 320×568の既存支持行の隠れは今回追加修正し、[最終画像](browser-after/compact-320-568-controls.png)で解消を確認。320×480の[極短画面](browser-after/compact-320-480-controls.png)では操作領域は確保するが、模型領域が約33pxまで小さくなり視認しづらい。390×844では十分な模型領域と操作領域がある。
- 実機の剛性・荷重・接触解析の検証ではなく、教材モデル内部の姿勢表示の確認。測定感度やYZの±仕様は変更していない。
