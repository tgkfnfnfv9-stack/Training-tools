# ページ切替・再抽選の独立ブラウザー確認

対象は生成済み `index.html`。修正担当とは別の担当が `tests/browser-page-redraw.cjs` を作成し、Chromium の実クリック・キー入力・ファイル選択・ダウンロード・ブラウザー履歴で確認した。製品コードは変更していない。期待する遷移はユーザー要望（新しいページ入場では新しい練習、画面内の操作では個体維持）から定め、アプリのルート関数を直接呼んでいない。観察のために個体 seed、支持高さ、軸位置、寸法、初期比較を読んだ。

## 確認内容

- 全7機種：設定開閉、支持点選択・微調整、X軸移動、デモ、測定図開閉では個体を保持。
- 全7機種：同じ機種カードへ再入場すると別 seed、支持高さ＝新個体の初期高さ、軸位置0、既定寸法・柱配置、支持点A・粗0.01 mm、初期比較＝新しい現在状態。
- 別機種へ移動して戻った際の新規開始。
- ブラウザーの戻る・進むで訓練画面へ戻った際の新規開始。
- 再読込後、機種カードから入った際の新規開始。
- 別文書へ実際に移動して戻った際の BFCache 復帰。`pageshow.persisted === true` を記録し、再抽選を確認。合成イベントではない。
- 全7機種：JSONによる寸法・柱配置・調整済み支持高さ・軸位置・個体の明示読込と、取込後の画面内操作での保持。
- 実ダウンロードしたJSONの全項目一致と、支持調整後にそのファイルを読み込んだ全項目復元。

寸法を手で変更するテスト用JSONでは、不整合になる旧寸法用の参考最良 `bestState` を省略し、取込後に再計算させた。旧寸法の `bestState` を残した不整合JSONは入力検証で拒否される。物理状態と個体は完全一致を要求し、読込後の全レコードは設定開閉で不変を要求した。未加工の実ダウンロードJSONでは `bestState` を含む全レコードが一致した。

## 独立確認で見つけた問題と再確認

既存の説明「画面を切り替えても個体・支持高さ・初期の基準は変えません」が新しいページ仕様と矛盾したため、修正担当へ通知。訓練画面内の軸選択・表示切替は保持し、機種選択等へ離れて戻ると新規開始する文へ修正済み。追加の確定した製品不一致は検出していない。

最終候補で **125/125 項目成功**。対象HTML SHA-256は `be6f6ceab33b285f2396e1048eeb940fe98b73dc6801b8448622f09571a49366`。結果と対象SHAは [navigation-browser.json](navigation-browser.json) に記録。画面証拠：

## 限界

Chromiumのこの実行環境での確認。Safari/iOS/Android実機のBFCache挙動は未確認。抽選値が前個体と確率的に近くなることはあり得るが、個体 seed が変わることと新初期値との一致を確認している。物理モデル・YZの正しさは本テストの対象外。
