## 独立手計算をブラウザーで照合した接触例

法線 n、面上点 P、本体 B、測定子方向 u に対し、伸びは `λ=n·(P-B)/(n·u)`。通常カウントは `(λ始-λ終)×10^6` µm。この式と固定寸法から期待値を作り、図や実装の符号表は参照していない。

- 固定 x=0 面、右側本体 x=.010→.00998 m: +20 µm。
- 同固定配置で新始点ゼロの逆走: -20 µm。
- 反対側本体 x=-.010→-.01002 m（同じ世界向きの移動）: -20 µm。
- 面/計器を共通に回転・平行移動: +20 µmを維持。
- 本体法線距離一定、測定子のみ0.002 rad傾斜: `10000(1-sec(0.002))` µm。逆走はその負。

これは接触計算の独立照合であり、機械の全材料点・取付具を実測したものではない。方向合わせ誤差は後述の補完検証、全機種の独立機構期待値は別担当の監査記録を参照する。

## 残る未確認と限界

連続経路すべての接触/干渉、支持全組合せ、全寸法変更、全ブラウザー/実機端末、公開後キャッシュは未確認。携帯スクリーンショットだけでダブルタップ抑止を証明しない。別の主担当ブラウザー検査では4画面寸法のピンチ/ドラッグ/ダブルタップ抑止と有限値不変も検証済み（`mobile-gesture-results.json`）。有限測定の局所取付け点と実物計器/マスタの物理的な取付け可否、弾性・荷重・接触反力は本監査の証明対象外。NCの右手系/A/C規約は模型の内部直交性とは別問題。

基準図はS面の展開で、画面右が機械右になるのは右法線のケースのみ。固定門形XZの図右は奥、横形YZは上、旋盤は右。模型の画面投影へ無条件に読み替えない。図の破線は始終本体位置の目安であり、捻れ経路の連続軌跡ではない。

## 最終補完（同一最終HTML、25条件）

`tests/browser-twist-edge-cases.cjs` と [追加JSON](edge-cases/browser-edge-cases.json)。追加6枚のスクリーンショットも同ディレクトリー。

- 横形の4支持列に勾配 `[.08,-.13,.16,-.05]` mm/mを線形補間した `h=x*g(z)` を入力。これはブラウザーへ解析用の非丸め支持高さを注入した入力であり、手動操作の.001 mm刻みとは区別する。中央Zの0→.3 m走査で支持境界の直前・境界・直後が存在することを実ブラウザーで確認。独立に `theta=atan(g/1000)`、高さH=.61 mの材料点 `[-H sin(theta), .66+H cos(theta), z]` を計算し、XZ/YZを接触式で照合。図の符号表は期待値に使っていない。
- 曲線 `x=.0001*y²` の0→.3 mは−9 µm。同じ固定面で指示だけ取り直した逆走は＋9 µm。終点接線から方向合わせを取り直した逆走は `−9 cos(atan(.00006))` µm。この違いをブラウザーの接触エンジンで検証。アプリの現在の再方向合わせ仕様を変更したものではない。
- 理想直線案内でも、基準器に±100 µradの方向合わせ誤差があると指示は `∓300000 sin(.0001)` µm（約∓30 µm）。機械誤差を入れずに照合。
- 全5機種で手前が面外となる実際の支持・軸・寸法状態を作り、全4 data-reading-microns が空になることを確認。
- 粗調整→上げる、微調整→上げる/下げるを実際にクリックし、+.01、+.001、−.001 mmを確認。
- 局所角度SVGのaria-describedbyが `localSquarenessNote`、有限SVGの説明が `squarenessMeasurementNote` で分かれ、有限図のscan要素が局所SVGへ混入しないことをDOM確認。

|機種|手前面外に使った(X,Y,Z)|支持幅/奥行き|
|---|---|---|
|小型立形|(-100,+100,-100)|既定|
|移動コラム|(-100,-100,-100)|各.5 m|
