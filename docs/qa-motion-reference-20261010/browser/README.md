## どこを基準に読むか

|測定|固定先・動く側|ゼロ／図の読み方の観測|
|---|---|---|
|横形 XY|マスタはパレット。計器は頭。Y で頭を上へ送る。|マスタから見ても計器は上へ。小図は「相対」「計器:頭」と表示。S の始点でゼロ。|
|横形 XZ/YZ|マスタはパレット。S 読みでは頭は静止、パレットを奥へ送る。|マスタから見た計器は手前へ。小図の固定マスタはこの相対座標の表示であり、世界に固定された器具という表示ではない。|
|横形 a/b|バーは主軸固定。計器はパレット側。|先端側から主軸側へ Z 走査。XY/XZ/YZ の直角マスタとは別配置。|
|旋盤面 X/Z|計器は主軸台側。刃物台の面を送る。|始点の面法線に合わせてゼロ。X 面が支持 B 操作で同じ整数になることを観測。|
|旋盤穴芯|主軸側計器。仮想ホルダは固定の公称 X 芯位置。|現 X スライダー位置そのものを測る検査ではないことが専用説明にある。図は主軸から見て a 左／b 上／c 右／d 下。|
|旋盤バー|バーは主軸固定。計器はタレット。|Z＋に送る。側面は奥から、上面は上から。始点 a でゼロ。心押台は対象外。|

測定の接触ゼロ、軸の中央、比較用の初期支持状態を同一視しない。全軸を＋100 にした状態でも、横形 Y の仮想走査は 0→+300 mm、Z は +150→+450 mm。旋盤では X 始点が 14.285714%、Z 始点が 57.142857% に戻り、300 mm の走査を確保する。3D は現在のスライダー位置に残る。横形には現在位置と接触ゼロ位置が同じとは限らない説明、旋盤には始点だけを内側へ戻す説明がある。

「抽選時の支持高さへ戻す」も実クリックした。軸は＋100 を維持し、支持高さだけが保存された初期高さへ一致する。初期比較は現在軸位置で行う説明と矛盾しない。測定を途中で再ゼロしていることを示す現表示はなかった。

## 検査履歴と限界

最初のハーネスは「調整の状態・手本」の details を開かずに初期復帰ボタンをクリックし、非表示 timeout となった。[最初の失敗ログ](before/harness-first-failure.txt)。製品のボタン不具合ではなく、実際に details を開く手順へ直して両版で通過した。

また、解析用 `h=.05xz` を JS で与えた直後に粗調整を行い、0.001 mm 刻み外の値が厳密往復するという誤った試験条件を置いた。B は −0.125120→−0.115000→−0.125000 mm となり、既存 UI の高さを小数 3 桁に丸める処理で4件が失敗した。[当該入力を残す完全記録](before/harness-offgrid-results.json.gz) / [失敗一覧](before/harness-offgrid-summary.json)。解析用ねじれ状態の可動確認は残し、通常の入力操作の往復確認は全支持 0 の UI 刻み上から開始して再実行した。これは入力条件を区別したもので、刻み外の保存値を操作した場合の丸め挙動が変わったという主張ではない。[最終 before](before/summary.json) / [最終 after](after/summary.json)。

旋盤 X−端では装飾工具とバーが重なる表示もある。任意の軸組合せで工具・治具の干渉を防ぐ模型ではなく、今回、衝突防止や送り制限を追加していない。この限界を固定バーが X 軸へ連れ動く不具合と混同しない。器具・ブラケットの実機組立可能性、連続経路の衝突、実機安全性は未確認。

PC と携帯幅の画像を目視確認した。[横形携帯の新説明](after/horizontal-width390-reference.png) / [旋盤携帯のバー測定](after/lathe-width390-second.png)。携帯ブラウザーのエミュレーションであり、実機 iPhone の確認ではない。
