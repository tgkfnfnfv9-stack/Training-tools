## 実際の操作

- X/Zスライダーの両端と全4組の複合端を操作。Xではタレット、Xスライド、工具ホルダ、工具だけが動く。Zではこれらと往復台が動く。主軸台・心押台・ベッドは固定。全ラベルの材料点の変位を個別に照合した。部材X両端差は内部zに+0.7 m、Z両端差は内部xに+1.4 m。
- 軸ボタンで選び実デモを開始／停止。同じ停止位置に最も近い整数スライダー位置を操作し、丸め0.5刻み以内の差だけ許して全ラベルの位置を比較した。デモとスライダーの可動部が一致。中央戻しも確認。
- 支持Bを粗0.010 mm上げ、下げて戻す。反対側の−0.010 mmも確認。支持調整で主軸回転TIRとX前面の固有成分は不変。Z面・穴芯・加工径差は支持状態に応答した。
- 実ダウンロードした [保存JSON](after/saved-state.json) を実ファイル入力で読み込み、非中央X/Z、支持高さ、個体と測定値が復帰した。
- 実マウス左右ドラッグ、左右ボタン、キーボード、Chromiumのタッチ入力による左スワイプで2ページを操作した。[左ドラッグ](after/lathe-mouse-slide-left.png)／[右ドラッグ](after/lathe-mouse-slide-right.png)／[タッチ左スワイプ](after/lathe-touch-slide-left.png)。
- 正面／側面／斜めの選択、マウスホイール拡大、表示誇張・理想輪郭の解除で、生の検査値が変わらないことを確認した。
- 320 / 390 / 1280 pxで文書の横はみ出しなし。4検査の文字が図のviewBox内へ収まることを実フォントのBBoxで確認した。

## 同じ個体で観測した値

すべて整数µm。X/Zは刃物台の各面検査、芯差Xは半径方向。前の直角度の値と同じ検査として比較しない。

|支持状態|主軸TIR a/b|刃物台 X/Z|穴芯 X/高さ|加工径差 心押あり/片持ち|
|---|---|---|---|---|
|平坦・軸中央|12 / 14|+4 / +8|+124 / −3|+10 / −34|
|Bを+0.010 mm|12 / 14|+4 / +9|+128 / −2|+12 / −32|
|Bを−0.010 mm|12 / 14|+4 / +7|+120 / −3|+9 / −35|
|Bを元へ戻す|12 / 14|+4 / +8|+124 / −3|+10 / −34|

平坦支持でXだけを動かしても各検査値は変わらなかった。穴芯は固定の公称X芯位置で測る仕様であり、Xスライダーをそのまま芯ずれ量とした検査ではない。Z両端で穴芯Xの生値は約+84.225 → +163.367 µmになった。これらは教材の実操作結果であり、実機の測定結果ではない。

## 指摘から再修正・再確認

初回に初ページのµm表示欠落を報告し、2検査の見出しへ単位が追加された。残っていた旧直角度の親ラベルも旋盤用へ更新された。

再確認時に穴芯bの文字がSVG上端から約3.5単位、X/Z・d・片持ちの値が下端から約1.4単位はみ出すことを検出した。[修正前の実BBox](review/font-bounds-before-fix.json)、[修正前320 px](review/font-bounds-320-second.png)。上段の文字位置を下げ、下段を上げる再修正後、320 / 390 / 1280 pxの全境界確認が成功した。最終画像を目視でも再確認した。

## 他6機種と検証の限界

他6機種は通常／固有精度の2ページ、390／1280 pxの24画面について、開始版と**全状態・数値・全ピクセルが完全一致**した。乱数種・支持平面・軸中央を同じに固定して比較した結果である。

この確認はLinux Chromiumの実ページ操作と描画検証。携帯幅とタッチ入力はエミュレーションであり、**実iPhone Safariは未確認**。Haas実機のブラケット、接触力、剛性、荷重、切削たわみやNC指令符号を認証する検証ではない。接触式と既知角度の独立数値検算は、別担当の測定監査と区別する。
